Open source · MIT

pg-lease-queue

The job-queue design from the taxi platform, rewritten as a small standalone library you can read and run. About 200 lines of Node.js and one Postgres table.

Exactly one worker per job
Claims use FOR UPDATE SKIP LOCKED, so parallel workers never pick the same job.
A dead worker cannot finish late
Every claim gets a new lease token. A worker whose lease expired is refused when it tries to complete.
Enqueue in your own transaction
If the business write rolls back, the job never existed.
Tested on real Postgres
CI runs PostgreSQL 13 and 16 with Node 18 and 22. Read the code →

How it fits together

api
Every business action checks the session, the role and the order state before it writes. Retried requests carry a stable key, so they never double-charge.
realtime
Each committed write is published once through Postgres NOTIFY, then filtered per socket by that user's read rules.
worker
A durable job queue in Postgres (FOR UPDATE SKIP LOCKED) with per-attempt lease tokens. It runs dispatch waves, push delivery and schedules.
federation
The two companies hand orders to each other over an HMAC-signed, replay-protected link with an ordered outbox. An outage delays money; it never loses or doubles it.

Production incidents I solved

Each one is written up in full in the Call Me case study.

"Some orders don't ring."

A 60-second recipient cache plus a token clean-up wiped the new push token of drivers who had just signed in again.

Cache versioned on login; token ownership claimed atomically.

Orders reached nobody after a deploy.

The cold-start path dropped the first orders after every backend restart.

Reproduced with a live drill on production using synthetic drivers; 0 of 3 lost after the fix.

The last drivers heard orders 4 s late.

Offers were written one driver at a time, 1,090 inserts per order.

One bulk write: 1.0 s end to end.

The customer saw no car.

A driver's phone clock ran 77 s ahead, so every GPS fix looked like it came from the future and the server refused it.

The server stamps all business times; phones send the age of a fix from their monotonic clock.

Distance dispatch silently stopped.

A read inside an event transaction saw its own staged write.

Root cause traced and fixed; the full trace is in the case study.

The worker ran out of memory every ~3.5 h.

Idle poll waiters were never released.

Waiters are released, and the worker now wakes on NOTIFY instead of polling.
